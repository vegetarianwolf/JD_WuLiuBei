# 原最终配送机不变的双来源辅助接力：历史覆盖与备选设计

日期：2026-10-15。状态：只读源码复核与设计，尚未实现、测试或运行官方实例。030 的原冻结源码、保存结果和严格审计失败记录均不作修改。本文件不声明成功，也不替代同预算性能对照。

## 已有覆盖与真正新增的范围

“保留原最终配送责任、无需补偿任务”已经尝试过，不能整体包装为新结构。

| 已有实现及诊断 | 实际结构 | 与本备选的差别 |
| --- | --- | --- |
| `batch_relay_refinement.py::_select_pairs/refine`，batch001 | 两件原来均由 C 最终配送；同一个其他飞机 A 承运两件 IN，C 承运两件 OUT；同站连续双件块。扫描32/2400任务对，IN/OUT各保4位置、每次保8组合；无采用 | 只有一个双件 feeder，没有两个不同 feeder 各收一件 |
| `directed_bundle_insertion.py::_pairs/_sender_options/_receiver_options`，batch010 | 原 C 实际同时载货的两件，仍由 C 在原 delivery slots 完成交付；同一个 A 分散取两件，允许源普通事件穿插。sender/receiver短名单8/4、组合8；无采用 | 仍是同一个 feeder；任务对限于原 C 已有同载组 |
| `anticipatory_mobile_handoff.py::refine`，batch015 | 原 C 的一/两件取货交另一飞机 A；C 空载先到移动会合点，原交付 slots 保留、责任不变。接收机晚到即拒绝；无采用 | 仍是单 feeder，且属另行声明的移动接触模型 |
| `inflight_relay_bundle.py::refine`，batch007 | 两机各自原已持有的两件互换最终交付责任，2↔2互惠交接 | 不是原最终配送机不变的辅助取货 |

生产 `uav_dispatch/alns.py::_build_relay_beam` 为单任务独立生成 IN/OUT，其中 IN 的 `counts_toward_k=False`；`_repair_relay` 每步只精修一个 chosen task。因而逐件修复理论上可到达下述两 feeder 同 C 的方案，但短名单与逐件决策不保证保存需要联合考虑的两任务组合。不能把“泛化 ALNS 可达”当成“已针对该双件原子邻域系统核验”。

016–030 的主要 repooling/window 原型则从 i 原属 A、j 原属 B 出发，把最终责任移交第三机 C，再用 C 的补偿任务恢复配额；六任务 sorting 要求选中任务跨原 owner。这些结构也不等价于本备选。

## 新的最小原子方案

从纯 DIRECT 完整输入中选原最终 owner 同为 C 的不同任务 i、j，选互不相同且均不等于 C 的 feeder A、B。对现有四站之一 H：

- A 收取 i，以 IN_i 交到 H；B 收取 j，以 IN_j 交到同一 H。
- C 删除原 i、j 取送计划，插入两件 OUT 后完成两项最终配送。要求两个 OUT take 连续，进入双取前空载，随后有严格正距离的双件共同载货航段。
- i、j 的最终 owner 始终是原 C；其余198任务先保持原 owner 与相对 signed-event 顺序。各机最终责任数原样，官方8×25不需要 k1/k2 补偿。IN 可在原载一件时插入，但全路线始终遵守容量2。

初版只用原四个固定 H，且 H 必须同时满足 i/j 原有 relay eligibility 与合法 IN/OUT 腿注册；不能为候选绕过原问题的可用站限制。原起点、站点、任务、速度和机队资源不变。固定站可使用题目既有地面交接等待语义；所有源 drop、接收 take、空飞、持货/空载等待与受影响普通任务时钟必须由完整 DAG 重算，不把早 drop 解释为免费移动接触。若未来改为移动会合，需要另建模型和独立物理审计。

在本仓 K 按最终配送责任计数的模型口径下，已完成25项最终交付的飞机仍可做 IN feeder，因为 IN 不增加最终责任 K；它从真实路线末点、真实完成时刻开始行动。不能把“完成自己的任务后”当成免费起点、零时刻或必然赶得上交接的证明，也不应只允许尾部插入而排除合法早期捎取。

## 搜索和证据边界

最接近的复用部件是 batch010 的同 owner 接收端和新窗口方法的单 IN 容量合法插入表。源端需拆成两套独立 IN_i/IN_j，按实际到站时刻联合 C 的空载 take gap、delivery 顺序和全部 native suffix 排名，而不是先独立只留几何最优再拼接。初版可同时保真实 J、原 late i/j 救期和中间截止窗口代表；它们只改变有限候选目录，不改变最终 J 目标。

任务对不必原本同载，尤其可检查分散 pickup 而 destination 接近的原 C 两件。仍需在下一次运行前冻结共同 pair/station/position/组合上限；选择、排序、完整快照与 guard 时间都纳入预算，记录未覆盖目录。仅 partial 源表或 optimistic C 窗口不能充当全解、可达性证明或完整 J 下界。

每个完整提案需独立证明：两项均为真实跨机、恰好两中继、原 final map 全部守恒、未选198项 owner/相对序不变、双 OUT 空载连续取件和正共载、完整覆盖/容量/K/因果合法。保存真实全局 N/L/D、所有事件和交付时钟、两源 availability、C 等待与原任务救回/新迟到归因。只有完整检查和快照均在 deadline 前、且严格改善原强输入加权 key 的方案才可采用。无改善保留原完整强解。

## DIRECT 对照不能由接力的 final map 限死

最少保留原 strong DIRECT guard，并让原 C 对 i/j 执行全部合法空载 gap×6种取送块顺序的真评分重插，包含两件共载或分送；不能强迫 DIRECT 到 H 或满足接力时窗。此固定 owner 对照只能解释同责任辅助取货的局部机制，不能单独证明优于强 DIRECT。

更强对照可在同一候选 family 为 A、B 各释放一个真实 whole-DIRECT donor，将 i、j 和这两 donor 的四任务按 A1/B1/C2 的全部12种责任分配独立重建。DIRECT 不继承 RELAY 的最终 i/j:C 限制，释放的 slot 必须来自实际删除、重插后恢复完整配额。两臂也可使用相同范围的普通任务重排/换机修复自由和总预算；若提供该后处理，必须共同开放和计时，保留真实全局评分与最终强输入 guard。不同对照的允许空间与实际完成数量需分别报告，不能把同 map 消融误称总体算法胜负。

这项备选试图减少配额补偿造成的原生任务损伤，但两 source 的真实 prefix、C 的早接货 gap、固定 H 绕行和有限目录仍可能使收益不足。030 的损伤闭包未改善输入，也不证明此结构必然有效或必须优先于其他方向。后续只应先做预声明的小型机制诊断，再由证据决定是否投入公平多种子实验。
