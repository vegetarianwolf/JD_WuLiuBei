## 可借鉴但尚未证明超越当前方案的差异

1. **两任务成对修复并释放第三任务的配额**：`src/uav_dispatch/paired_repair.py:55` 同时评价两任务、保留六种合法取送顺序和穿插候选；第 144 行起在 K 满额时移出第三个完整任务，维持责任数量。
   这比本仓周期任务标签交换提供不同的打包邻域，适合做加权版本的独立同预算消融；它首先是 DIRECT 搜索改进，不能自动归为中继收益。
2. **从首轮开始的集成调度和有限非单调探索**：`src/uav_dispatch/integrated_alns.py` 让普通 DIRECT、成对修复、双向中继共享当前/最优解和总时钟；特殊算子时间目标约 20%，失败或无变化不奖励，暂差交接给予有限普通修复后回退。
   它不同于本仓原 95% DIRECT 预热后短中继阶段，可借鉴时间分配、保留交接再修复的机制。最新最终解仍为零中继，现有数据不能证明这种调度带来真实运输收益。
3. **按实际身份追踪延迟奖励**：`src/uav_dispatch/operator_learning.py` 只给仍保留所引入交接、随后形成改进的探索记有限延迟奖励，避免把普通后续改进全部归给中继。这是学习/诊断归因改动，需要按当前加权目标重新核验。
4. **无变化候选不奖励及算子成本诊断**：本次提交修正 no_move 统计，并以成本和组合验证将常规池从 9×5 减为 8×3。短试筛选有多重比较，长试仅少量种子；不宜直接照搬删减名单。

源码中确有批量局部 MIP 历史后端，但本次最新默认版本的结果来自精简集成搜索。
未发现应据此宣称“强化学习/神经网络/QUBO 优化已获证实”的证据；这里的独立学习是轻量算子与延迟奖励管理，不是这些方法的性能证明。
