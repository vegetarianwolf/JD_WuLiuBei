# 240 秒 Relay vs Direct 配对墙钟对比实验报告（调整配置）

日期：2026-08-15
环境：Windows 11 / Python 3.13.3；200 tasks / 8 UAV / capacity=2 / K=25
配置：seed 2026080500–2026080502（3 种子配对），candidate_limit=48（rank 24 / exact 48），
初始解 = regret-2 直送构造（三种子共享同一初始路线）
Relay 网络：**4 个中继站，每任务 2 个候选站，绕行比 2.0，兜底开启**，选址种子 42
Relay 求解：分阶段 `solve_relay_staged`（80% DIRECT 预热 + 20% Relay 搜索），
**构造后中继播种 + 跨机精化开启**；probe 0.40 / max 6，plan_beam 6，leg_beam 8，
global_limit 5，sample_every 3
运行方式：`run_relay_comparison.py --output-dir results/relay_adjusted_240s --wall-seed-count 3 --wall-time-limit 240 --wall-safety-margin 2`
判优规则：严格词典序（late_count → total_lateness_min → distance_km），逐种子配对比较

## 6. 分析

1. **词典序质量**：三种子 late_count 全部持平（65/66/67），胜负由第二目标决定。Relay
   的跨机接驳（每解 3~5 个）把部分任务的运力从超载机转移到余量机，直接压缩总逾期分钟；
   seed 00/02 总逾期分别少 2.56/7.95 min，足以在词典序上翻盘。
2. **中继被采用**：从旧配置 0 个提升到 4.33 个/解。四个杠杆共同生效——更多站点与每任务
   2 候选（搜索空间扩大）、绕行比 1.3→2.0（走廊放宽）、构造后播种（初始解即含中继）、
   精化 + 扩大探测（搜索阶段持续改进）。
3. **吞吐代价**：Relay 吞吐降至 Direct 的 83%，但以 17% 的迭代损失换取第二目标净改善
   8.12 min（相对旧 Relay 结果），在 240 s 预算下是划算的。
4. **确定性**：三条轨迹均为确定性算法；同 seed 重跑解一致（已记录 solution SHA-256）。
5. **预热比例补充实验（证伪记录）**：30 s 下把预热从 0.80 调至 0.60 反而使 Relay 更差
   （最终逾期 (82,80,83) vs (81,80,80)）——缩短 DIRECT 预热削弱起点，而该数据集上
   Relay 搜索边际改进率（~1 任务/5~12 s）远低于 DIRECT（~5 任务/6 s），因此 0.80 保持默认。

## 7. 结论

- 在 **4 站 / 每任务 2 候选 / 绕行 2.0 + 构造后播种 + 跨机精化 + 扩大探测** 的配置下，
  Relay 在 240 s 配对墙钟实验中 **2:1 胜出**：第一目标持平，第二目标全面改善（均值
  -3.11 min），第三目标略优（-0.88 km）。这是本仓库首个 Relay 在配对实验中胜出的配置。
- 局限：该数据集紧耦合（capacity=2、K=25），Relay 尚不能降低逾期任务数（第一目标），
  但能显著压缩逾期分钟并略微减少里程；中继作为"第二目标优化能力"已得到实证。
- 如需进一步冲击第一目标，可考虑：中继友好的数据集（任务聚集、跨机紧约束更极端）、
  更大 relay probe 预算，或在中继阶段引入"仅当 DIRECT 插入濒临逾期时才生成中继"的定向策略。
