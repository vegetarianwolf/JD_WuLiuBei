# 移动同步会合：与固定站模型分开的研究扩展

此文件在首个 mobile 优化单元运行前写入。官方 CSV、200任务、8架机、容量2、
0.9 km/min、软截止期、全部完成、开放式航程与原始起点槽位保持不变。
当前加权J及其归一化尺度保持不变；每机K25仍按已明确采用的最终交付责任口径。
这属于论文中继扩展，不把原题未定义的中继说成原题直接规则。

固定站模型允许包裹缓存在原4站；本移动模型的新增坐标没有地面缓存功能。
一次移动会合只能由两架机使用一次，每侧转交等量1或2件已经实际在载的包裹。
早到机飞到会合坐标后必须等另一机到场，在等待期间仍持有原包裹。
所有卸取事件在 T=max(两机到达时刻) 同时发生，装卸时间沿用模型的0分钟假设。
两机原取货点保持，等量交换对应交付责任和交付槽；其余任务原机与相对访问顺序保持。

候选位置来自交换后的实际航段交点、四端点几何中位数、兼顾到达时间的候选，
不由新免费起点或隐含车辆产生。无人机从原起点一路连续飞行，候选插入带来的
全部空飞、载货飞行与同步等待进入最终送达时刻和航程。旧站点和已接受会合点
均不可随意移动；新增点只在对应完整会合被采用时进入输出模型。

为复用现有优化器，普通relay DAG把早机卸货记在较早到达时刻，但双向接货依赖
已把双方离场推到T。独立 mobile 审计再增加双方前驱至对侧卸货的真实飞行边，
重建全部同步物理事件，验证早机持货等待与容量，证明最终送达时刻、逾期和航程
与生产完整核验一致。普通DAG卸货时刻不作为空中物理交接时刻；新增点的
package-cache telemetry不作为本模型实际地面缓存。物理明细另存 mobile_meetings。

新批manifest在START之前绑定方法、候选上限、输入、源码、模型、种子和预算。
强DIRECT checkpoint上加20秒仅为机制诊断；若候选有实质改善，再从共同初解做
全预算DIRECT对照，并用新种子检验。不用累加预算的改善宣称同预算胜出，
也不把移动会合模型成绩与固定4站成绩混算。

当前实例的所有任务事先已知，因此使用确定性剩余路线和真实接力时间前瞻。
统计需求预测属于未来动态放单扩展，本批没有新增任务到达过程或模拟预测收益。
