# 补偿任务筛选的完整移除代价复核（v1）

2026-10-15，ROOT 与独立模型审查代理针对冻结的
`algorithm/experiments/relay_repooling_exchange.py::_select_groups` 自行分析。
这是下一方法的设计依据，不是文献结论或性能结果；batch021 仍仅增加整段
receiver 枚举缓存，没有采用本文的新选择器。

## 从实际保存解发现的问题

batch020 的共同八组选择器中，所有 i/j 原本均已逾期，所有 k1/k2 原本均准时。
第一组 i=23、j=184 的原逾期分别为32.919、41.781分钟；补偿73、115分别
提前27.361、37.509分钟送达。数据来自 batch015 的实际强 DIRECT checkpoint，
而不是一个改变任务或起点的小例。此现象支持检查筛选偏好，但不证明另选补偿
一定能让完整中继解更好。

原选择器对每个补偿 k 的分数为：

`q_A_old(k) = J(source_insert_delta_A(k) + (0, 0, remove_distance_C(k)))`。

IN/OUT 四项尚未完整重建；这个局部数值只作候选排序。问题有两处：

1. C 删除 k 后，k 自身原有逾期及其后续原任务的时钟变化没有计入 N/L，
   只计了距离。原本已逾期的 k 可能因这个遗漏而失去应有的移除信用。
2. 对 k1/k2 直接相加单次移除信用，即使只看距离也不一般可加；同时删除
   会改变公共 detour 和后继任务的截止期跨越。

## 只用于排序的修正

输入限定为当前完整纯 DIRECT；所有 route score 都从原真实 home 出发、使用
冻结的官方任务、截止期、速度、N/L/D 定义与加权尺度。

令 `S_C` 为 C 原路线完整三项 score，`S_C(-k)` 为删除 k 的 P/D 后的实际
路线回放 score。单任务可用：

`q_A(k) = J(source_insert_delta_A(k) + S_C(-k) - S_C)`。

单项仅用于有限候选池初筛。对真正有向补偿对，应使用：

`q_pair(k1,k2) = J(source_insert_delta_A(k1) + source_insert_delta_B(k2)
                    + S_C(-{k1,k2}) - S_C)`。

这里双移除贡献只加一次，替代两个单移除项；不能在原单项和上再叠加双移除。
C 单删/双删 score 可按真实 C 路线及任务集合缓存。原 A/B 删除 i/j 的代价
在同一 i/j/C family 内为常数；跨 family 排名若仍用原几何与风险项，依旧
是启发式。尚未加入 C 接送 i/j 的完整代价，也没预测源机 IN 或移动交接等待，
所以此值绝不是完整提案分数、下界或采用凭证。

## 为何要同时检查双移除

反例一：C 原点起飞，依次走 k1=(1→0)、k2=(1→0)、n=(0→0)，n 截止3。
n 原在4送达，晚1；单删任一 k 后 n 在2准时。把两个单删信用相加会对 n
错误记两次 N/L 改善；真正双删只改善一次。

反例二：C 原点出发，在5同时取 k1/k2，再在0送达两件。单删任一 k 仍需
10km，双删两件则省10km。单删和又会漏掉公共 detour 的协同收益。

这些是代价非可加性的算术例证，不是官方机队性能试验。

## 下一实验的有限覆盖设计

可在每侧固定保留原几何前六项与完整 C 移除收益前六项的并集（最多12项），
对两侧所有不同任务的有向 pair 先算一次真正 joint removal score，再选该
family 的有限优胜组合。最多144个 pair，重复任务的 pair 不合法；同池最多
132个不同有向 pair。若先各截为三项才组合，会继续漏掉单项看起来差、joint
却有协同收益的 pair，必须明确这是较小邻域。

DIRECT/RELAY 必须共用完全相同的候选池、排序、完整选择记录与 SHA、预算和
输出组数上限。原任务、homes、资源及最终完整采用/独立 source 审计保持。
单例改善、选择器分数变小或修复公式本身，均不能替代实际200任务完整结果，
更不能据此宣称中继显著优于强 DIRECT。
