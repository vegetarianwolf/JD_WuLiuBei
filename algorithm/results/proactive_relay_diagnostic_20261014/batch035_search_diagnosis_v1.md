# 035：找到真实前缀收益后，完整恢复为什么仍未改善

035 两臂都完成了付费 raw 构造、两个 seed、每个 seed 两轮动态责任修复，最终均保留025强 DIRECT guard：N59、L1790.632129 min、D578.534685 km、J0.434215788788。RELAY 确实选进了控制到站的零损伤前缀，也实际分支了不同 owner；失败不能归为“前缀没有进入闭包”或“代码仍只固定原责任”。实际完整恢复没有保住删除预览里的提前量，有限 beam 的 q 很快收敛，最后若干 donor 的 owner 选项已受此前保留状态限制；回补后完整方案更差，但不能据此认定每件 donor 自身都变差。

本诊断只读 batch035 原文件，不运行优化器，不重复全批审计。ROOT 保存的 `batch035/audit.json` 严格通过，无辅助字段例外。本次另独立重放 **4个** RELAY 最终保留层的最小J方案（2 seed × 2轮），N/L/D、所有event/delivery时刻、每机25件和两次真实跨机均与保存证据吻合。完整 source SHA、结果与细表在同名 JSON。

## 正 gain 前缀确实入选；低编号 donor 有明确来源

RELAY 四个 closure 都实际打开8机，每轮删12件，q均按实际 whole-DIRECT 删除产生。每一个 source到站、C到站、selected delivery及两个额外临界 delivery **方向所选代表全部保留**。这不表示全部正gain任务都入选：例如第一个seed每个source仍各有23件正单删提前任务未选，C有21件未选。第二轮 variant1还会明确轮换头部，未必保留第一轮的最大单删代表。

| R seed / 轮 | 删12中正因果gain件数 | 其中自身delivery与base不变 | 两个source代表 / C代表 | 真正q |
| --- | ---: | ---: | --- | --- |
| 最小J / 0 | 8 | 8 | 160、27 / 198 | [1,2,1,1,2,1,2,2] |
| 最小J / 1 | 8 | 8 | 16、57 / 168 | [1,2,1,1,2,1,2,2] |
| 真分散最小J / 0 | 7 | 5 | 27、160 / 85 | [1,1,1,1,2,1,2,3] |
| 真分散最小J / 1 | 7 | 6 | 57、16 / 126 | [1,1,1,1,2,1,2,3] |

最小J seed 第一轮，160单删使a124提前3.337627分钟，27使a166提前2.146976分钟，198使C到站提前2.386575分钟；三件自身原交付时刻均未变。这正是设计要找的零损伤因果前缀。删除全12件后，该不完整DAG的两source分别真实提前5.298450 / 2.492942分钟，C提前2.904054分钟。**这是删除预览，不能相加当恢复后收益或完整J下界。**

低编号1/2/3/19等并非遗漏了同机更大的正gain代表：它们来自非当前目标因果相关飞机的预留 donor，该飞机任务在本轮排名采用的正时钟gain、newlate、正ΔL、正交付延误均为0；末位按任务ID打破平局。第二轮同一政策转取第二头部，例如3→12、2→7、1→9。代码没有估计它们在某个具体接收责任/位置下的回补成本，所以“真实开了槽”和“开了好回补的槽”是不同事实。

选择证据的 `selection_events` 前8条是 donor 预留；**beam恢复次序并非照此前8条执行**。`removed_task_ids` 又按gain重排。最小J seed 第一轮实际分组是：

`[160,198] → [27,126] → [32,195] → [117,64] → [1,2] → [3,19]`。

高gain的source/C任务已经在前；不能把本轮失败写成“donor先恢复，critical prefix放到最后”。最后四项主要是无正时钟gain的外机donor。

## owner确实分支，但保留层很早固定了剩余槽

各层枚举所有当时q>0的owner；保存的候选owner序列与真实全局delta探测数量证明它没有固定为旧四张assignment表。每层只保留6个同coverage状态，其不同q向量数如下：

| R seed / 轮 | 六层保留状态的不同q向量数 |
| --- | --- |
| 最小J / 0 | 4, 2, 3, **1**, 1, 1 |
| 最小J / 1 | 5, 3, 3, 2, 2, **1** |
| 真分散最小J / 0 | 5, 4, **1**, 1, 1, 1 |
| 真分散最小J / 1 | 4, 3, 2, **1**, 1, 1 |

具体地，最小J seed 第一轮在 `[117,64]` 层后，6个保留状态都把117交给机0、64交给机4，q同为 `[0,1,1,1,0,1,0,0]`。117原责任机1→0已消费机0真实donor3释放的槽。下一层后只剩q=`[0,1,1,0,0,0,0,0]`，最后两项只能使用机1、2的两个槽；最终六个保留状态均选择3→机1、19→机2，另一个对应也曾被探测。最终最小J完整方案中，task3在机1于49.176886分钟交付，仍超过due34.8，但它原raw于70.172008分钟交付，**自身反而提前20.995122分钟，原本就已迟到**。新增迟到的是117、14、98、136，令完整N从59到63。这个局部路径跨出了原三机角色，但整体没有带来收益；数据没有证明换成12或34等其它donor就能获胜。

这里不能把前一层较低的partial J与完整J之差称为“丢失的可达收益”：两个coverage不同，待补donor尚未计入。不过可以从实际q、owner、完整时钟证明，某个前缀任务的去向和其目的机回补任务没有作为一个完整条件交换一起结清；稍早的有限保留已让末层失去其它owner选项。真分散seed第一轮第三层后也只剩一个q向量；DIRECT有同类现象。

## 完整恢复把到站提前量如何用掉

下表取各轮最终6个保留状态中J最低的一项；不混同helper返回的raw incumbent。四项均做了本次独立完整物理重放。N/L/D可在同名JSON逐项查看。

| R seed / 轮 | 最终层最小J / N | 换责任普通任务 | 完整a_i / a_j / c（min） |
| --- | --- | --- | --- |
| 最小J / 0 | .452064544443 / 63 | 3、117 | 81.577683 / 80.499857 / 86.810353 |
| 最小J / 1 | .450909282274 / 61 | 12、26、64、117 | 81.577683 / 86.368746 / 86.375271 |
| 真分散最小J / 0 | .437467413507 / 59 | 无，完整路线等于raw | 57.971942 / 65.744618 / 64.164977 |
| 真分散最小J / 1 | .441138782526 / 60 | 无，但事件位置改变 | 57.971942 / 65.744618 / 64.947346 |

第一个seed原a124/a166/c为81.577683 / 80.499857 / 80.085332；第二个seed原a178/a190/c为57.971942 / 65.744618 / 64.164977。因此：前者两个source的最佳完整到站没有提前，C反而晚约6.3–6.7分钟；后者第一轮精确重建raw，第二轮source仍未提前。helper最终均返回原R seed，而总wrapper因其仍输强DIRECT继续保guard。

这不是所有owner分支都恢复原责任：前两行有实际跨机周期与外机参与。但入选critical source任务如160/27/16/57在这些最终最优层中仍回原source，删除预览的时钟提前没有在完整重构中保住。大多数新owner机会只存在于被探测或更早被beam淘汰的状态，不能拿候选分支数量当运输性能。

## 当前证据支持的下一动作与限制

应优先检验**条件化的因果前缀任务—目的机真实donor完整回补目录**：比较某件critical任务t去机b时，b具体哪件whole-DIRECT任务d能回补到原机a，并在同一完整两任务候选里真实重算q/C2/DAG/J，然后决定是否把该条件交换送入后续修复。候选d不应只受本轮既定12件或低ID tie约束。这个方向已形成读审设计 [`conditional_donor_completion_repair_design_v1.md`](../../../papers/notes/proactive_relay_20261014/conditional_donor_completion_repair_design_v1.md)，尚未实现或注册新运行；本诊断不实现、不预注册新预算或运行。

成对任务/责任cycle本身早已在旧实现出现；这里尚未覆盖的是按真实因果目标和目的机回补代价联合生成donor，而不是把pair算子改名。它也不保证中继有效或远胜DIRECT。DIRECT必须具有对应whole任务自由和同总wall，pins为空，最终仍完整严格比较原强guard。当前单次种子、有限cap/位置frontier/beam结果没有排除其他更好前缀、donor或完整路线。
