# 第二轮候选：跨路线成对串移除

实现日期：2026-10-13。新研究开关 `enable_multiroute_string_destroy=False`；算子名
`multiroute_string`。默认注册表仍为 9 个破坏与 5 个修复算子。

## 选择依据

父批缓存候选在集群固定 100 轮的命中率分别为 1.54%、1.86%，10 秒筛选
分别为 3.23%、3.04%。这说明本批完整候选的跨迭代复用不足以直接支持提速
判断，父批两组集群均按词典序落后；本轮改测独立的搜索邻域，不组合缓存或
预算降温，也不将父批胜负并入第二轮。

Christiaens 与 Vanden Berghe 的 *Slack Induction by String Removals for
Vehicle Routing Problems*（2020，[DOI](https://doi.org/10.1287/trsc.2019.0914)）
提供相邻串移除的文献线索。本实现仅借鉴“成块移除”的思想，保留原有修复和
接受机制，未实现原文完整 SISRs 或 blinking insertion；文献核实层级与原始
API 返回由第二轮 `literature/` 另行保存。

## 具体实现

1. 在已有任务中随机选空间种子，采用取货点距离加送货点距离度量相关性。
2. 通常选择种子所在路线与另一条最近的非空路线。两条路线任务总量不足时，
   按相关性追加非空路线，以保证精确移除指定数量；一个任务或一条占用路线
   时允许自然退化。
3. 在选中路线间均衡分配移除数量；每条路线从取货任务顺序中截取包含相关
   锚点的一段连续子串，子串起点随机选择。
4. 对每个选中任务同时移除完整取送对。已有修复算子、容量、任务数、截止期、
   词典序评分和完整 incumbent 复算不变。

与已有 `route_segment` 的区别是跨多个空间相关路线释放槽位；与
`assignment_destroy` 的区别是按连续取货顺序成块移除，而非按单任务移除收益
分散选点。完整 8×25 满载集群可同时释放两架无人机的任务槽，是否改善第一
目标仍须独立短预算配对检验。

仅在多机 DIRECT 搜索中向破坏算子池增加一个独立权重；单机与实际 Relay
阶段不启用，构造初解不变。分阶段 Relay 的 DIRECT 预热可按现有开关传递
语义使用该候选，实际 Relay 阶段无作用。

## 小型验证

`algorithm/tests/test_multiroute_string_destroy.py`：23 项测试通过，0.08 秒。
覆盖不同路线长度、空路线、容量二交错取送、精确移除数量、完整任务对、
连续任务段、跨路线槽位、空间近邻与距离并列、内部超大请求与空路线边界、初解不变、单机/实际 Relay
搜索决策无变化、短固定轮数的合法性与完整最优解保留。尚未运行墙钟基准，
此处没有质量改善结论。
