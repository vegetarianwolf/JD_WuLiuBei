及不含时钟的最优轨迹完全一致；这只证明本次配对的决策等价，不代表缓存普遍提速。

## 冻结协议

用户选择 10 秒初筛、最多 30 秒扩大验证；精简中文仪表盘；仅比较本轮与当前 main；
允许 30 秒三种子多数获胜的探索晋级，即使一次退化也完成预定种子。
原题语义不变：25 任务单机、200 任务 / 8 架，容量 2、每机最多 25 项、0.9 km/min，
原点起飞、全部任务完成、末单不返航。按 `(逾期数, 总逾期分钟, 航程)` 判优；
总逾期分钟为项目次级约定。

时长从数据读取前至完整核验与 JSON 写出后计；不含进程启动及模块导入。构造从预算扣除，
另预留 1 秒收尾，故墙钟测试通常在约 9 秒或 29 秒返回。固定迭代阶段提前完成即可返回。
求解顺序运行并按种子轮换版本顺序；没有并发求解、换种子或重跑择优。
首次分析另进行了 30 轮 cProfile 热路径检查（约 1.93 秒），仅用于实现选型，不参与本批评分。

`manifest.json` 绑定官方输入、源码 ZIP、原执行脚本、种子、预算和门槛；完整解保存在
`run_solutions/`。`validation.json` 完整复算路线、三级评分、预算及独立晋级决定。
原题、原始数据、作者稿和旧 `final_*` 结果未改写；旧论文仍须使用其原冻结源码重建。

## 重建与重放

仅重建审计和报告不启动求解：

```sh
PYTHONPATH=algorithm/src .venv/bin/python -m algorithm.experiments.audit_method_trials
.venv/bin/python -m algorithm.experiments.render_method_trials_report
```

若后续批次已冻结父批核验文件，不应在原目录重新核验父批（时间戳会改变其指纹）；
使用副本核验，或先重建父批再创建新的后续批次。

重放求解使用独立 checkout：恢复 `sources/candidate.zip` 中模块和三份归档执行脚本，
将运行器输出参数指向**新的空目录**，依次执行 `run_method_trials prepare` 与 `run`。
两研究开关在源码快照中均默认关闭，各候选通过显式配置单独启用。墙钟成绩受机器负载影响，
相同种子不保证原成绩逐位复现；源快照和配置用于还原方法及协议，不承诺时间确定性。
