# 加权直送的算法改进：完整请求互换与惰性修复

本轮以此前实际运行的加权版本为基线，进一步改变搜索邻域和修复工作量。
两方案保持同一目标、输入、初解和随机种子，只有一个正式候选组合；
不把历史词典序方案、其他场景或旧批次的分数混入对照。

## 题目与固定目标

官方完整200项任务，8架无人机，每机至多25项、载荷至多2件，速度0.9 km/min。
全部机从原点出发，所有任务必须同机先取后送、恰好完成一次，不计末单后的返航。
无中继，无预部署。因200=8×25，每架机终局必须恰好承接25项。

加权系数及归一化尺度原样沿用上一批，不做权重再调优：

```text
J = 0.50 × 逾期数 / 200
  + 0.25 × 总逾期分钟 / 4464.183540734935
  + 0.25 × 总航程公里 / 775.7731679286865
```

共同词典序构造初解为108项逾期、4464.183540734935 min总逾期、
775.7731679286865 km航程。每方案各自构造后核对路线指纹，再开启相同加权规则。
题目直接关注按时数/率、航程与可控求解时间；总逾期分钟是项目次级指标，J不是官方评分。

## 两个方案

- `weighted_baseline`：复制父批 `weighted_direct_single_seed_20261014` 的实际加权
  solver ZIP，并核对其精确字节指纹。本轮重新求解，不复用父批的最终成绩。
- `weighted_exchange_lazy`：新增完整请求原位互换，同时显式开启已有
  `enable_lazy_repair`。固定目标、算子池、温度、构造、候选位置上限、相邻强化和
  原有末端步骤均保留。正式对照评估整个组合，不把组合收益单独归因于某一步。

完整请求互换把两条路线的请求a、b各自两个取/送标签对称替换为另一请求。
每条路线的正负事件序列不变，所以单件等载荷DIRECT模型中的每个前缀载荷、
每机累计任务数和同机先取后送保持；交错取送也适用，不要求零载荷切点。
飞行时间会改变，仍须精确评两条路线的三项物理指标，改善后完整规范核验。
这是结合本题约束的适配，不宣称原样复现CVRP的SWAP*。

启发式最多选64个逾期/孤立anchor，从至多7条其他路线的中点x/y索引中取邻居，
每anchor保留4个partner，去重后至多256个候选。代理包括两请求旧时钟的逾期变化
和精确受影响弧长变化，只负责排序；代理为正不作为拒绝交换的依据。
该短名单可能遗漏更优交换，不保证邻域最优。

互换在原home→tail→home末端步骤之后执行，共享既有至多0.1秒的预留预算，
另留2 ms供外层核验，不增加总时限或主循环随机调用。实际Relay阶段不启用。
只有截止之前完整核验的改善可保留；超时继续返回已核验checkpoint。

惰性修复对deadline/slack只计算真正可被选择的静态短名单：风险引导时前三项，
否则一项。12任务、3机、30轮的加权固定迭代检查确认开/关的路线、物理最优轨迹、
接受数、算子统计和权重一致。该组成主要减少无用评价，是否使240秒终局改善
仍以正式对照为准。新互换开关及已有惰性修复的公共默认均保持关闭。

## 正式协议

共同新种子为 `2026101461`，顺序运行基线与候选各一次，每方案240秒端到端上限。
计时包含读取、初解构造、主搜索、末端强化、完整核验及解JSON写出，不含Python导入。
搜索预算扣除本方案实测构造时间与1秒收尾预留。所有退化原样保留，不换种子、不择优重跑。
计时期间不运行测试、额外优化、审计或报告渲染；只继续检索、阅读与文本编辑。
主机不是独占环境，单种子结果不支持稳定性、统计显著性或速度因果判断。

第一次基线优化器完成并写出完整解后，执行器直接序列化只读元数据对象而失败，
运行响应与已计算的端到端时间未落盘。该孤立解、原协议和执行器快照完整归档于
`failed_recording/`，不补造精确用时，不纳入正式配对。仅修复四个诊断字段的JSON
归一化方式，再用同一算法、配置、权重和种子重新冻结完整两臂；没有按终值调参。
本轮因此包含一次记录失败和两次正式有效求解，共三次优化器执行。
详情及证据指纹见 `execution_notes.json`；这属于记录故障恢复，不能当作择优取最好的一次。

`manifest.json`同时绑定父批、固定目标、初解、两个实际执行solver ZIP、当前生产源码
和三份执行脚本指纹。新增算法源码与生产默认关闭状态均通过源码预检。

## 机制探测与文献边界

`diagnostics/swap_probe.json`是在已保存的父批解上探测128个候选，说明现有邻域存在
遗漏；`diagnostics/swap_primitive_probe.json`只调用一次已实现有界邻域，用时0.032212秒，
精评207个候选，接受1个改善。两者都是额外机制证据，完全不是新的240秒ALNS成绩，
不计入正式样本、均值或胜负。

新增文献见[阅读笔记](../../../papers/notes/weighted_improvement_20261014/reading_notes.md)：
实际Google Scholar检索、Crossref核验、Diana/Dessouky及Vidal等原始全文关键章节，
另有知网托管期刊与《计算机工程》的官方中文摘要。知网高级检索受浏览器限制，
公开题录/摘要的成功访问与失败分别记录，没有声称查到全文。
文献提供方法动机，本题载荷符号不变性及具体短名单参数是本项目工程适配。
paper-lookup的Scientific Agent Skills软件参考已按技能要求列入报告，不能作为算法效果证据。

## 查看和重建

[HTML指标对比报告](index.html)内嵌全部图表数据，离线可用。
`runs.json`与`run_solutions/`保留两份完整实测；`audit.json`不导入求解器或加权适配器，
用官方CSV和几何回放复算初解与最终解，核验硬约束、指标、共同J、轨迹及指纹。
中间轨迹只有分数记录，不能当作每个中间路线都独立复算过。

仅审计或重建，不启动新的求解：

```bash
.venv/bin/python algorithm/experiments/audit_weighted_method_pair.py
.venv/bin/python algorithm/experiments/render_weighted_method_report.py
```

恢复本提交的源码，在新目录产生独立重放批次；墙钟可能不同，不能覆盖原成绩：

```bash
.venv/bin/python algorithm/experiments/run_weighted_method_pair.py prepare \
  --output-dir algorithm/results/weighted_method_replay_NEW
.venv/bin/python algorithm/experiments/run_weighted_method_pair.py run \
  --output-dir algorithm/results/weighted_method_replay_NEW
```
