# 同一长测配对的 regret 搜索诊断

仅分析上一批 `confirm / fleet200 / seed 2026101321` 的 baseline 与 allocation，均为 240 秒预算。没有启动求解；完整路线已从官方 CSV 独立复算。所有派生数字、200 项任务明细和来源 SHA-256 见 [diagnostics.json](diagnostics.json)。

## 直接证据

- 同一seed1321的240秒运行内，allocation在[5, 10, 30, 60, 120]秒检查点词典序领先，在[180, 239]秒落后；不引用其他种子的短测来解释长测。
- 共同迭代上限16671时baseline为64逾期、allocation为65；最终分别63和65。吞吐差不能单独解释回退。
- baseline完成17398轮、allocation完成16671轮；搜索吞吐分别73.00和69.96轮/秒。
- allocation在46.89秒首次达到65逾期，之后未再下降；baseline在168.91秒达到64，238.58秒达到63。
- allocation全局最优更新371次，高于baseline的327次；较多三级得分更新不等同于较少逾期任务。
- regret2使用占比由18.28%升至35.61%，其接受率由38.70%升至80.36%。这是各自整段轨迹的描述统计。
- 最终17项任务从基线按时变成候选逾期，15项反向改善，逾期数净变化+2；总逾期分钟变化-182.533，航程变化-36.386km。

## 机制推断与尚未识别的混杂

- **待检验机制：**候选较早降低逾期数，随后在65这一第一目标水平上持续改善总逾期/航程；这与搜索集中于当前第一目标水平附近的解一致，但现有数据不能证明陷入哪个局部最优。
- **待检验机制：**regret2更高的累计接受、奖励与使用占比，可能和自适应权重的正反馈及搜索方向改变有关；缺少时序权重、配对算子和被拒候选日志，不能断言它导致长测退化。
- **待检验机制：**应优先在后续独立试验拆开lazy与route-distinct开关，并记录第一目标改善次数/归属与阶段算子统计，再检验候选机制；本诊断未启动这些试验。
- **混杂：**候选同时启用 lazy repair 和跨无人机 regret；相同种子在路径分歧后不代表随机选择逐轮匹配。只有一个已完成长测配对，且按 baseline 后 allocation 的顺序运行，不能排除主机负载与顺序影响。
- **日志缺口：**缺少中间路线、当前状态、拒绝候选、算子耗时、时序权重和 destroy–repair 联合统计；不能定位某个具体算子或某项任务导致的长测退化，也不能由累计改善数作显著性判断。
