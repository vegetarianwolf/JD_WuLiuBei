# 跨无人机 regret：退化诊断与优化复测

[离线报告](index.html) · [上一轮原始报告](../optimization_20261013/index.initial.html)

本批次专门回应“短测领先、长测落后”。所有新结果与上一轮分开保存；原题、
官方数据、论文及 `final_*` 冻结产物没有修改。原题条件保持容量 2、每机
上限 25、15 m/s、原点起飞、全部任务完成、最后不返航。

## 为什么发生反转

旧候选并没有丢失已经找到的最优解，而是在逾期任务数 65 上较早停滞。
其总逾期分钟和航程继续改善，基线稍后将逾期数降至 64、63，造成相对优势
反转。以相同完成迭代数比较，在 16671 轮处也是基线 64 对候选 65，
因此仅用吞吐差异解释不够。[历史轨迹与完整复算](diagnostics/README.md)
保存时间／迭代检查点、算子统计和任务状态变化。

代码与局部修复探针发现一个可复现的问题：当空余任务槽分布在少于 k 架
无人机上，跨机 regret-k 会把全部待插任务赋为 inf；同一架无人机上仍有
多个插入位置的信息被丢掉。36 次局部修复共 360 个插入轮次中，regret2
为 39/180 次全 inf，regret3 为 63/180 次；其中还有多个待插任务的轮次
分别为 21、45。探针仅从一个旧最终解出发且关闭风险指导，其频率不能外推
为长测全程发生率，也不能证明这就是长测反转的唯一原因。

另一个待检验机制是搜索集中：旧跨机 regret2 累计使用占比由 18.28% 升至
35.61%，接受率由 38.70% 升至 80.36%。现有记录不足以把高接受率与退化
建立因果关系；新组合候选用于检验保留两类邻域是否更稳健。

## 两个可独立关闭的候选

- A `fallback`：不同无人机备选不足 k 个时，回退到现有位置 regret；
  真实插入位置也不足时保留 inf。缓存请求数量、精确插入、初解不变。
- B `portfolio`：保留位置 regret2/3，增加独立加权的跨机
  `route_regret2/3`，并启用 A 的回退。只扩展多机 DIRECT 搜索，默认算子
  注册表不改；单机和 Relay 搜索阶段继续使用原算子池。分阶段 Relay 的
  DIRECT 预热可用新算子，最终 Relay metadata 的 active=False 仅描述
  最后阶段，不能据此否认预热已使用新机制。

两者均包含此前 lazy 修复开关；上一轮固定迭代 6 组检查保持路线、得分和
决策一致，支持其为等价计算改写，但不能视作所有输入上的等价证明。此次
新增机制开关默认关闭；是否修改默认算法只依据完整晋级结果。

## 复算与重建

以下命令只读取已保存解，不运行新的 ALNS。须先审计子批，再构建子批页面，
最后生成主报告；更新旧入口会保留旧 HTML 为 `index.initial.html`。

```bash
PYTHONPATH=algorithm/src:. .venv/bin/python -m algorithm.experiments.audit_optimization_results \
  --output-dir algorithm/results/regret_followup_20261013
PYTHONPATH=algorithm/src:. .venv/bin/python -m algorithm.experiments.audit_optimization_results \
  --output-dir algorithm/results/regret_followup_20261013/supplemental_trial
.venv/bin/python -m algorithm.experiments.render_optimization_report \
  --output-dir algorithm/results/regret_followup_20261013/supplemental_trial
.venv/bin/python -m algorithm.experiments.render_regret_followup_report --update-previous-entry
```

重放应在新空目录执行 `run_regret_followup prepare` / `run`，随后在其
`supplemental_trial` 执行 `run_regret_portfolio_validation prepare` / `run`。
后者仅接受 A 已完成且中测失败、B 已通过原初筛的父批；原父批不得再修改。
重放历史实验须恢复 `sources/` 的脚本与 solver，基线 Git 对象必须存在。
固定墙钟时限受机器与负载影响，相同种子不保证逐位复现最终成绩。
旧论文重建仍须匹配其原始源码，不能绕过源码指纹检查。
